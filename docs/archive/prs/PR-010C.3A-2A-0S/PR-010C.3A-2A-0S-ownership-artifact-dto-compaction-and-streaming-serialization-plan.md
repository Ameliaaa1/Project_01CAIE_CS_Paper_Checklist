# PR-010C.3A-2A-0S Ownership Artifact DTO Compaction and Streaming Serialization Plan

## 1. 阶段目的

本阶段用于解决：

```text
PR-010C.3A-2A-0
Single-PDF Ownership Runtime Integration
```

在 artifact 写出阶段发生的：

```text
RangeError: Invalid string length
at JSON.stringify
```

当前已确认：

```text
Ownership model import: PASS
Ownership model runtime execution: PASS
Single-PDF selection: PASS
Production write: false
Artifact serialization: FAIL
```

失败原因不是 ownership model 未执行，而是 source-span sidecar artifact 在当前 DTO 结构下过大，`JSON.stringify()` 无法一次性构建完整字符串。

本阶段目标是：

1. 找出 artifact 体积异常膨胀的字段；
2. 将 runtime object 转换为扁平、可审计、可关联的 evidence DTO；
3. 对大型数组采用流式 JSON 写出；
4. 保持 atomic write、SHA-256 和 record count；
5. 重新运行同一份单 PDF smoke test；
6. 不修改 candidate、Stable IDs、Production、Frontend 或 rendering index。

### 2.2 当前阻塞

当前失败阶段：

```text
artifact serialization
```

原始异常：

```text
RangeError: Invalid string length
at JSON.stringify
at atomicWrite
at writeJson
at runOwnershipSmoke
```

这说明当前写入方式类似：

```js
await fs.writeFile(
  filePath,
  JSON.stringify(value, null, 2)
);
```

该方式会先在内存中生成完整 JSON 字符串。

对于超大对象，这会导致：

```text
single giant string allocation
→ V8 string length limit
→ RangeError
```

## 3. 可能的 DTO 膨胀来源

单份 PDF 的 source-span artifact 正常情况下不应大到无法序列化。

因此必须检查是否存在对象重复嵌套，例如每个 span 中携带：

```text
完整 page object
完整 geometry object
完整 items[]
完整 visualLine object
完整 anchors[]
完整 ownershipAssignments[]
parent object
children object
siblings object
raw runtime object
```

如果每条 span 都复制整页或整份 geometry，数据规模可能从：

```text
O(n)
```

膨胀为：

```text
O(n²)
```

本阶段必须先确认真实字段分布，再进行 DTO 压平。

## 9. JSON Safety Validation

在写文件前，必须运行 JSON safety validator。

至少检查：

```text
circular references
BigInt
function
symbol
Error object
Map
Set
class instance
undefined-heavy object
forbidden nested runtime fields
```

处理规则：

- circular reference：拒绝；
- BigInt：显式转为 string，并记录 conversion；
- function/symbol：拒绝；
- Map/Set：通过明确 DTO 转换；
- Error：转换为 `{name,message,stack}`；
- class instance：转换为 plain object DTO；
- undefined：按 schema 明确删除或转为 null。

不得通过 `JSON.stringify` replacer 静默吞掉所有异常字段。

## 10. Streaming Serialization

### 10.1 小型 Artifact

以下文件可继续普通 JSON 写入：

```text
smoke report
evidence manifest
capture execution report
serialization diagnostic
```

---

### 10.2 大型 Artifact

以下文件必须使用 streaming JSON array：

```text
source spans
visual lines
anchor candidates
structural anchors
ownership assignments
```

不得先对完整数组执行：

```js
JSON.stringify(records)
```

---

### 10.3 Streaming Writer 要求

建议接口：

```js
writeJsonArrayStream(filePath, records, options)
```

必须：

1. 使用 `.tmp` 文件；
2. 写入 `[`；
3. 逐条 `JSON.stringify(record)`；
4. 逐条写入逗号和换行；
5. 写入 `]`；
6. 等待 stream 完成；
7. fsync/close；
8. rename 到正式路径；
9. 计算 SHA-256；
10. 返回 recordCount 和 sizeBytes。

---

### 10.4 Backpressure

必须处理 Node stream backpressure。

示意：

```js
if (!stream.write(chunk)) {
  await once(stream, "drain");
}
```

不得在大型数组循环中无视 `write()` 的返回值。

---

### 10.5 Error Handling

任何 stream error 必须：

- 终止写入；
- 保留 capture execution report；
- 删除不完整 `.tmp`；
- 不生成成功 manifest；
- 记录 failed artifact；
- 保持 `productionWrite=false`。
