## 2. 已确认问题

### 2.1 Visual Line bbox 无效

当前 visual-line artifact 中存在：

```json
{
  "bbox": {
    "x0": 56.7307014465332,
    "y0": 54.70770263671875,
    "x1": null,
    "y1": null
  }
}
```

说明 visual-line bbox 聚合过程中产生了非有限值，或者读取了错误字段。

常见原因包括：

```text
读取 span.x1 / span.y1，而实际坐标位于 span.bbox.x1 / span.bbox.y1
Math.max() 输入包含 undefined
空数组聚合
NaN / Infinity 被 JSON.stringify() 转为 null
```

---

### 2.2 页面阅读顺序反向

当前 visual order 会先出现页面底部内容，例如：

```text
© UCLES 2024
[Turn over
```

之后才出现页面顶部标题。

这说明 visual-line builder 使用了错误的 y 轴排序方向。

当前 PDF geometry 更接近：

```text
origin = BOTTOM_LEFT
y 越大，位置越靠上
```

因此 top-to-bottom reading order 应使用：

```text
page ascending
y descending
x ascending
```

或者先统一转换为 top-origin 坐标，再使用 y ascending。

---

### 2.3 竖排 margin text 把整页连接成一条 line

奇数页存在：

```text
DO NOT WRITE IN THIS MARGIN
```

这类竖排文字的 bbox 高而窄，可能覆盖接近整页高度。

如果 horizontal line grouping 使用 vertical overlap，并允许可传递合并，则该竖排 span 会成为 bridge：

```text
vertical margin span
→ 与页面多行产生 overlap
→ 将多条正常水平行串成一个巨大 visual line
```

当前部分奇数页只有极少 visual lines，说明该问题已经真实发生。

## 6. 修复一：Visual Line bbox 聚合

### 6.1 正确字段来源

visual-line bbox 必须从所属 source spans 的：

```js
span.bbox.x0
span.bbox.y0
span.bbox.x1
span.bbox.y1
```

计算。

不得读取：

```js
span.x0
span.y0
span.x1
span.y1
```

除非真实 DTO 明确采用该结构。

---

### 6.2 聚合规则

示例：

```js
function aggregateLineBBox(spans) {
  const valid = spans.filter((span) => {
    const bbox = span?.bbox;
    return bbox &&
      Number.isFinite(bbox.x0) &&
      Number.isFinite(bbox.y0) &&
      Number.isFinite(bbox.x1) &&
      Number.isFinite(bbox.y1);
  });

  if (valid.length === 0) {
    return null;
  }

  return {
    x0: Math.min(...valid.map((span) => span.bbox.x0)),
    y0: Math.min(...valid.map((span) => span.bbox.y0)),
    x1: Math.max(...valid.map((span) => span.bbox.x1)),
    y1: Math.max(...valid.map((span) => span.bbox.y1))
  };
}
```

最终实现可以不同，但必须满足相同语义。

---

### 6.3 硬验证

每条 visual line 写出前必须验证：

```js
const bboxValid =
  line.bbox &&
  Number.isFinite(line.bbox.x0) &&
  Number.isFinite(line.bbox.y0) &&
  Number.isFinite(line.bbox.x1) &&
  Number.isFinite(line.bbox.y1) &&
  line.bbox.x1 >= line.bbox.x0 &&
  line.bbox.y1 >= line.bbox.y0;
```

如果任一 visual line bbox 无效：

```text
geometry validation = FAIL
stage status = BLOCKED
```

不得将 NaN、Infinity 或 undefined 序列化为 null 后继续报告 PASS。

## 7. 修复二：统一坐标系统与阅读顺序

### 7.1 识别真实坐标系统

运行时必须记录 geometry extraction 使用的坐标系统，例如：

```json
{
  "coordinateSystem": {
    "origin": "BOTTOM_LEFT",
    "xDirection": "RIGHT",
    "yDirection": "UP",
    "readingOrder": "TOP_TO_BOTTOM"
  }
}
```

如果 extraction path 已经转换为 top-origin，则应记录真实值，不得硬编码。

---

### 7.2 排序规则

对于 bottom-left origin：

```text
page ascending
line top position descending
line left position ascending
```

对于 top-left origin：

```text
page ascending
line top position ascending
line left position ascending
```

排序逻辑必须由明确的 coordinate-system metadata 决定，不能由不同模块分别猜测。

---

### 7.3 稳定排序

相同 y 区间的 line 必须使用确定性 tie-breaker：

```text
x position
minimum globalOrder
visualLineId
```

相同 PDF 重跑两次，visual-line 顺序必须一致。

## 8. 修复三：竖排 Margin Span 检测

### 8.1 分类目标

将类似：

```text
DO NOT WRITE IN THIS MARGIN
```

的竖排或边栏内容分类为：

```text
VERTICAL_MARGIN_TEXT
```

或项目已有的等价枚举：

```text
MARGIN_TEXT
EXCLUDED_PAGE_MATERIAL
VERTICAL_TEXT
```

不得为了匹配该字符串而硬编码完整文本。

---

### 8.2 检测证据

优先使用 extraction 已有字段：

```text
rotation
writingDirection
orientation
regionType
matrix
```

如果 extraction 不提供这些字段，可以结合 geometry：

```text
height >> width
height > pageHeight × 合理阈值
width 接近单字符宽度
位于页面左侧或右侧边缘
text 由多个竖排字符组成
```

示例启发式：

```js
const width = bbox.x1 - bbox.x0;
const height = bbox.y1 - bbox.y0;

const likelyVerticalMargin =
  height > pageHeight * 0.45 &&
  width < medianHorizontalSpanHeight * 0.75 &&
  isNearPageEdge(bbox, pageBBox);
```

阈值必须根据当前 PDF evidence 调整，不得把示例数字视为不可变规范。

---

### 8.3 隔离行为

被分类为 vertical margin 的 span：

- 保留在 source-spans artifact；
- 保留 bbox、text、stable spanId；
- 不参与 horizontal visual-line grouping；
- 不允许作为 transitive grouping bridge；
- 不参与结构 anchor detection；
- ownership 可以归入 `EXCLUDED_PAGE_MATERIAL`；
- 可单独形成 vertical-region evidence，但不是正常 visual line。

---

## 9. 修复四：限制 Horizontal Line Grouping

正常 visual line 只能合并满足以下条件的 spans：

```text
同一页
相同或兼容 orientation
垂直中心或 baseline 足够接近
span 高度处于合理范围
不存在整页高度的 bbox
```

禁止仅依赖任意 vertical overlap 进行可传递 union。

特别禁止：

```text
一个超高 span 与多条水平行重叠
→ 将所有水平行合并成一个 group
```

---

### 9.1 Oversized Line Gate

增加 oversized visual-line 检测，至少检查：

```text
spanCount
line bbox height
line bbox height / page height
text length
vertical extent
```

若一条 horizontal visual line：

```text
覆盖页面高度的大比例
包含异常多 spans
同时包含多个明显不同 y 区间
```

则记录：

```text
OVERSIZED_VISUAL_LINE
```

并使本阶段状态为 `BLOCKED`。

阈值应通过当前 PDF 的正常行分布确定，不应仅依赖一个随意常数。

## 16. 必须执行的测试

至少覆盖：

### 16.1 Visual Line bbox

- 所有 bbox 字段为有限数字；
- `x1 >= x0`；
- `y1 >= y0`；
- 不允许 null；
- 不允许 NaN；
- 不允许 Infinity。

### 16.2 Reading Order

- Page 内从顶部到底部；
- 相同 y 行从左到右；
- 相同输入双跑顺序一致。

### 16.3 Vertical Margin Isolation

- 高而窄的边栏 span 被分类为 vertical margin；
- 不参与 horizontal line grouping；
- 不创建 anchor；
- 不成为 transitive bridge。

### 16.4 Normal Horizontal Lines

- 正常题干仍能正确分行；
- `[2]` 等右侧 marks 不因 margin 修复丢失；
- 图表或代码块中的正常横向内容不被错误排除。

### 16.5 Oversized Line Detection

- 人工 fixture 中的超高 vertical span 不得把多行串联；
- oversized line 必须触发 validation failure。

### 16.6 Stable IDs

相同 PDF 双跑：

```text
source span IDs 一致
visual line IDs 一致
visual order 一致
```

### 16.7 Safety

```text
candidateTextChanged=false
stableIdsChanged=false
productionWrite=false
```
