本阶段用于将正式的 Canonical Boundary Contract Validator 接入已经完成验证的 canonical ownership artifacts，并在 216 份 Question Paper 全量 corpus 上执行正式边界契约验证。

## 2. 核心目标

本阶段必须完成：

1. 定位仓库中真实的 Canonical Boundary Contract 与 validator 实现；
2. 确认实际 contract version、validator entrypoint 和 rule registry；
3. 将 1C 生成的 source spans、visual lines、anchors 和 ownership assignments 转换为 validator 的正式输入；
4. 确保调用的是 Canonical Boundary Validator，而不是 Question Rendering Contract Validator；
5. 在 1B 的 10 份回归试卷上先执行 wiring smoke；
6. 在 216 份全量 corpus 上执行正式 contract validation；
7. 为每个 validator issue 保留真实 source-span、visual-line、anchor 和 ownership evidence；
8. 确保 issues 直接来自 validator 输出，不从目标数量、semantic diff 或 summary report 推导；
9. 验证 validator 的 rule coverage、record coverage 和 determinism；
10. 区分 Wiring PASS 与 Corpus Contract PASS；
11. 保持 1C 输入 artifacts 不变；
12. 保持 candidate、Stable IDs、Frontend 和 Production 不变；
13. 为 Production Readiness Gate 提供可信的正式 contract 结果。

---

## 3. 非目标

本阶段禁止：

- 修改 1C 已冻结 artifacts；
- 修改 Production；
- 修改 Frontend；
- 修改 candidate question text；
- 修改 Stable Question IDs；
- 修改 Parent IDs 或 Child IDs；
- 将 validator 结果直接写入 production store；
- 使用 Question Rendering Contract 代替 Canonical Boundary Contract；
- 将 summary diff 转换为伪 validator issues；
- 根据预期 issue 数量填充 `issues[]`；
- 将 skipped rules 计为 PASS；
- validator 未执行时输出 0 issue；
- 用默认 owner 掩盖 ownership gap；
- 删除失败 paper；
- 因问题数量过多而只保留部分 issues；
- 在 evidence 缺失时仍将 issue 标为 complete；
- 修改 contract rule 以迎合当前 corpus 输出；
- 在本阶段启动 Production migration；
- 创建 manifest self-hash；
- 在 manifest 完成后修改已登记文件。

如果 validator 发现真实 contract issue，应在本阶段内记录、定位、修复并重跑，而不是降低契约标准。

## 9. Boundary 构建

每个 question boundary 必须由 typed ownership 和 structural anchors 决定。

规则：

```text
Question starts at its structural anchor.
Question content includes spans assigned to its owner.
Child ends before the next sibling or ancestor-level structural anchor.
Top-level question ends before the next top-level question.
Marks remain MARK_ALLOCATION evidence.
Excluded page material never enters semantic boundary.
```

跨页问题必须使用：

```text
runtime anchor page
owned-page sequence
next real structural anchor
```

不得使用过期的 Production page range 作为唯一边界依据。

## 21. Validator Issue 修复规则

如果正式 validator 发现真实问题：

1. 保留 raw validator issue；
2. 保留完整 evidence；
3. 判断问题属于：
   - ownership runtime defect；
   - validator input adapter defect；
   - validator implementation defect；
   - contract rule defect；
   - corpus data defect；
4. 修复最小必要模块；
5. 增加 regression fixture；
6. 先重跑失败 paper；
7. 重跑 10-paper wiring smoke；
8. 重跑完整 216-paper validator；
9. 重跑 validator determinism；
10. 更新 repair log。

不得：

