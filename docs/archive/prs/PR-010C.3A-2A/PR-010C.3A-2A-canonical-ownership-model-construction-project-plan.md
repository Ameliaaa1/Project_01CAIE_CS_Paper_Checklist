# PR-010C.3A-2A Canonical Ownership Model Construction Project Plan

## 1. 文档目的

本项目文档用于定义并实施：

```text
PR-010C.3A-2A Canonical Ownership Model Construction
```

当前 PR-010C.3A-2 无法完成，不是因为 evidence serializer 或 capture hook 本身失败，而是因为现有 parser 架构中没有显式构建并保留以下运行时对象：

```text
source spans
visual lines
structural anchors
ownership assignments
```

因此，目前无法真实执行：

```text
CANONICAL_QUESTION_BOUNDARY_CONTRACT v1.1.0
```

也无法生成符合 Contract 要求的 Canonical ownership evidence。

本阶段的目标不是修复具体题目，也不是生成最终 migration candidate，而是在 parser 上游建立一条真实、可追溯、可验证的 ownership 数据链。

## 6. Source Span Model

### 6.1 目标

将 PDF parser 输出的原始 token/span 转换为稳定的 Source Span 对象。

每个 span 必须具有：

```json
{
  "spanId": "stable-span-id",
  "paperId": "9618-2024-ON-12-QP",
  "page": 1,
  "blockIndex": 0,
  "lineIndex": 0,
  "spanIndex": 0,
  "text": "Index Register",
  "normalizedText": "Index Register",
  "bbox": {
    "x0": 0,
    "y0": 0,
    "x1": 0,
    "y1": 0
  },
  "font": {
    "name": null,
    "size": null,
    "weight": null,
    "style": null
  },
  "rawOrder": 0,
  "globalOrder": 0
}
```

---

### 6.2 Stable Span ID

`spanId` 必须：

- 同一次 dry-run 中唯一；
- 相同 PDF 输入重复运行时稳定；
- 不依赖随机 UUID；
- 不依赖生成时间；
- 不依赖最终数组索引；
- 可用于 issue、ownership 和 source trace 关联。

建议生成方式：

```text
sha256(
  paperId
  + page
  + blockIndex
  + lineIndex
  + spanIndex
  + normalizedText
  + normalized bbox
)
```

输出示例：

```text
SPAN-9618-2024-ON-12-P03-7F2A91C84D3E
```

---

### 6.3 Source Span 校验

必须检查：

```text
spanId uniqueness
paperId presence
page validity
bbox validity
text type
stable hash reproducibility
```

如果 bbox 不存在，必须明确：

```text
geometryStatus = MISSING
```

不得伪造零坐标。

---

## 7. Visual Line Model

### 7.1 目标

将 Source Spans 按 geometry-first 规则组合成视觉行。

每条 Visual Line 至少包含：

```json
{
  "visualLineId": "stable-line-id",
  "paperId": "9618-2024-ON-12-QP",
  "page": 1,
  "visualOrder": 0,
  "spanIds": [],
  "text": "...",
  "bbox": {
    "x0": 0,
    "y0": 0,
    "x1": 0,
    "y1": 0
  }
}
```

---

### 7.2 Line Grouping Rule

同一视觉行可使用以下规则之一判定：

```text
verticalOverlapRatio >= 0.50
```

或：

```text
centerDistance <= 0.35 × medianSpanHeight
```

阈值必须：

- 在代码中集中配置；
- 在 report 中输出；
- 通过 fixture 测试；
- 不得散落在多个函数中。

---

### 7.3 Line Internal Ordering

同一 visual line 内按以下顺序排列：

```text
x0 ascending
x1 ascending
rawOrder ascending
spanId ascending
```

不同 visual line 之间按：

```text
page ascending
y0 ascending
x0 ascending
visualLineId ascending
```

必须保证 deterministic。

---

## 8. Structural Anchor Model

### 8.1 Anchor 类型

至少支持：

```text
TOP_LEVEL_QUESTION
ALPHA_CHILD
ROMAN_CHILD
MARK_ALLOCATION
RESPONSE_AREA_MARKER
TABLE_LABEL
CODE_LABEL
NON_STRUCTURAL_TOKEN
UNRESOLVED
```

---

### 8.2 Anchor DTO

```json
{
  "anchorId": "stable-anchor-id",
  "paperId": "9618-2024-ON-12-QP",
  "page": 3,
  "spanIds": ["..."],
  "anchorType": "ROMAN_CHILD",
  "label": "(ix)",
  "normalizedLabel": "ix",
  "visualLineId": "...",
  "context": {
    "precedingText": "Index Register",
    "followingText": "",
    "lineText": "Index Register (IX)"
  },
  "classificationConfidence": 0.18,
  "classificationReason": "Roman numeral occurs inside a technical term.",
  "finalClassification": "NON_STRUCTURAL_TOKEN"
}
```

---

### 8.3 Context-Aware Classification

不得只使用正则表达式：

```text
^\([ivxlcdm]+\)$
```

来认定 Roman child。

必须综合：

- token 是否位于行首；
- token 左侧是否存在 semantic text；
- 是否存在父级 alpha anchor；
- 是否处于 expected hierarchy state；
- 与前一行的垂直和水平关系；
- 是否位于技术术语、寄存器名或缩写中；
- 是否后接完整题干；
- 是否与相邻 structural anchors 对齐。

---

### 8.4 已知 Fixture

必须增加：

```text
Index Register (IX)
```

预期：

```text
(IX) = NON_STRUCTURAL_TOKEN
```

不得创建：

```text
Q3-A-IX
```

同时还应覆盖：

```text
(i)
(ii)
(iii)
```

在真正子题结构中的合法情况。

## 10. Ownership Assignment Model

### 10.1 Ownership 原则

所有 semantic span 必须满足：

```text
owner count = 1
```

不得出现：

```text
owner count = 0
owner count > 1
```

---

### 10.2 Owner Types

至少支持：

```text
PARENT_PREAMBLE
CHILD_QUESTION
NESTED_CHILD_QUESTION
MARK_ALLOCATION
RESPONSE_AREA
NEXT_TOP_LEVEL_QUESTION
EXCLUDED_PAGE_MATERIAL
TABLE_STRUCTURE
CODE_STRUCTURE
UNRESOLVED
```

---

### 10.3 Ownership Assignment DTO

```json
{
  "assignmentId": "stable-assignment-id",
  "spanId": "stable-span-id",
  "paperId": "9618-2024-ON-12-QP",
  "assignedOwner": {
    "ownerType": "CHILD_QUESTION",
    "ownerId": "9618-2024-ON-12-Q3-A",
    "ownerPath": ["a"]
  },
  "assignmentReason": "Span occurs after anchor (a) and before next sibling anchor.",
  "precedingAnchorId": "...",
  "terminatingAnchorId": "...",
  "confidence": 1.0
}
```

---

### 10.4 Ownership Precedence

建议采用以下优先级：

```text
1. EXCLUDED_PAGE_MATERIAL
2. RESPONSE_AREA
3. MARK_ALLOCATION
4. STRUCTURAL_ANCHOR
5. NESTED_CHILD_QUESTION
6. CHILD_QUESTION
7. PARENT_PREAMBLE
8. TABLE_STRUCTURE
9. CODE_STRUCTURE
10. UNRESOLVED
```

优先级必须记录在 Contract implementation report 中。

---

### 10.5 Ownership Boundary

一个 child 的 semantic ownership 从：

```text
child anchor 之后
```

开始，到以下任一条件前结束：

```text
下一个同级 child anchor
父级结构终止
下一个 top-level question
明确 excluded material
page continuation boundary resolved
```

Mark allocation、response area 和 structural labels 必须单独归属，不得进入 child semantic text。

---

## 11. Hierarchy State Machine

必须显式维护 hierarchy state：

```text
TOP_LEVEL
ALPHA_CHILD
ROMAN_CHILD
NESTED_ROMAN_CHILD
```

合法转换示例：

```text
TOP_LEVEL → ALPHA_CHILD
ALPHA_CHILD → ROMAN_CHILD
ROMAN_CHILD → ROMAN_CHILD
ROMAN_CHILD → ALPHA_CHILD
ALPHA_CHILD → TOP_LEVEL
```

非法转换必须进入：

```text
INVALID_HIERARCHY_TRANSITION
```

不能仅靠字符串匹配推导层级。
