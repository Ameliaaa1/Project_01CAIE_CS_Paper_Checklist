# PR-010C.3A-2A-1 Full-Corpus Ownership Integration and Evidence Capture Project Plan

## 1. 文档目的

本项目文档用于定义并实施：

```text
PR-010C.3A-2A-1
Full-Corpus Ownership Integration and Evidence Capture
```

PR-010C.3A-2A 已建立 Canonical Ownership Model 的基础模块，包括：

- stable Source Span ID；
- geometry-first Visual Line；
- context-aware Roman anchor classification；
- ownership assignment DTO；
- classification registry；
- owner registry；
- `Index Register (IX)` fixture。

但该模型目前仍是上游基础层，尚未接入完整的 216 份 PDF dry-run，也尚未生成 PR-010C.3A-2A 要求的全量 evidence artifacts。

本阶段负责把已经建立的 ownership model 接入真实 parser 运行路径，并对全部 0478、9618 PDF 执行只读 capture、validation 和 determinism 检查。

## 6. Source Span Full-Corpus Capture

### 6.1 Required Fields

每个 Source Span 必须至少包含：

```json
{
  "spanId": "stable-span-id",
  "paperId": "9618-2024-ON-12-QP",
  "page": 1,
  "blockIndex": 0,
  "lineIndex": 0,
  "spanIndex": 0,
  "text": "...",
  "normalizedText": "...",
  "bbox": {
    "x0": 0,
    "y0": 0,
    "x1": 0,
    "y1": 0
  },
  "font": {
    "name": null,
    "size": null,
    "weight": null,
    "style": null
  },
  "rawOrder": 0,
  "globalOrder": 0,
  "geometryStatus": "AVAILABLE"
}
```

---

### 6.2 Geometry Rules

如果 PDF parser 能提供真实 bbox：

```text
geometryStatus = AVAILABLE
```

如果某个 span 缺失 bbox：

```text
geometryStatus = MISSING
bbox = null
```

不得使用：

```json
{
  "x0": 0,
  "y0": 0,
  "x1": 0,
  "y1": 0
}
```

冒充真实坐标。

所有 missing geometry 必须进入 validation report。

---

### 6.3 Span ID Determinism

相同 PDF 输入重复运行时：

```text
spanId(first run) = spanId(second run)
```

不得依赖：

```text
random UUID
generatedAt
temporary array position
process-specific memory state
```

---

## 7. Visual Line Full-Corpus Construction

### 7.1 Required Fields

```json
{
  "visualLineId": "stable-line-id",
  "paperId": "9618-2024-ON-12-QP",
  "page": 1,
  "visualOrder": 0,
  "spanIds": [],
  "text": "...",
  "bbox": {
    "x0": 0,
    "y0": 0,
    "x1": 0,
    "y1": 0
  },
  "groupingEvidence": {
    "verticalOverlapRatio": 0.0,
    "centerDistance": 0.0,
    "medianSpanHeight": 0.0
  }
}
```

---

### 7.2 Geometry-First Requirement

Visual Line 顺序必须主要由：

```text
page
y coordinate
x coordinate
```

决定。

原始 PDF content array order 只能作为最后 tie-break，不能作为主要顺序。

---

### 7.3 Deterministic Tie-Break

建议顺序：

```text
page ascending
y0 ascending
x0 ascending
rawOrder ascending
spanId ascending
```

相同输入重复运行，visual line hash 必须一致。

### 8.2 Context Evidence

每个疑似 anchor 必须保留：

```text

```

---

### 8.3 Roman Anchor Safety

不得仅凭：

```text
^\([ivxlcdm]+\)$
```

认定 Roman child。

必须检查：

- 是否处于行首或合理缩进位置；
- 是否存在合法父级 alpha child；
- 是否符合 hierarchy state；
- 是否与相邻 Roman child 对齐；
- 是否位于技术术语中；
- 是否是寄存器名、缩写或正文内容的一部分。

## 9. Ownership Assignment Full-Corpus Construction

### 9.1 Required Rule

所有 semantic spans 必须满足：

```text
owner count = 1
```

---

### 9.2 Assignment Fields

```json
{
  "assignmentId": "stable-assignment-id",
  "spanId": "stable-span-id",
  "paperId": "9618-2024-ON-12-QP",
  "assignedOwner": {
    "ownerType": "CHILD_QUESTION",
    "ownerId": "9618-2024-ON-12-Q3-A",
    "ownerPath": ["a"]
  },
  "precedingAnchorId": "...",
  "terminatingAnchorId": "...",
  "assignmentReason": "...",
  "confidence": 1.0
}
```

---

### 9.3 Owner Assignment Rules

Ownership 必须遵守：

```text
structural anchor 不进入 semantic text owner
mark allocation 单独归属
response area 单独归属
excluded material 单独归属
child text 在当前 child anchor 后开始
child text 在下一个同级 anchor 前结束
nested child 不得吞并 sibling text
next top-level question 不得归属上一题
```

---

### 9.4 Unresolved Ownership

如果 owner 不能确定：

```text
ownerType = UNRESOLVED
```

并生成明确 validation finding。

不得：

- 随机选择一个 owner；
- 默认归入 previous child；
- 默认归入 parent；
- 静默删除 span。
