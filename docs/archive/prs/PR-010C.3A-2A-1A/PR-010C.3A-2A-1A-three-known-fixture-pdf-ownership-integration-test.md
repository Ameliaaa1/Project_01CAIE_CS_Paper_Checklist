# PR-010C.3A-2A-1A Three Known-Fixture PDF Ownership Integration Test

## 1. 阶段定位

本阶段用于将已经在单 PDF 上通过的 canonical ownership runtime，扩展到 **3 份已知高风险试卷**，验证它在不同版式、题号层级、marks、response area、barcode 和 margin text 条件下仍然稳定。

当前基线：

```text
PR-010C.3A-2A-0A Anchor Classification: PASS
PR-010C.3A-2A-0S Serialization Closeout: CLOSED
PR-010C.3A-2A-0V Visual-Line Repair: CLOSED
PR-010C.3A-2A-0 Single-PDF Ownership Runtime Integration: PASS
Production Write: false
```

本阶段编号：

```text
PR-010C.3A-2A-1A
```

后续建议顺序：

```text
1A: 3 Known-Fixture PDFs
→ 1B: 10 PDF Integration
→ 1C: 216 PDF Full Corpus
→ Canonical Validator Wiring
```

---

## 2. 本阶段目标

必须完成：

1. 选择并冻结 3 份代表不同风险类型的试卷；
2. 对 3 份试卷运行完整 ownership runtime；
3. 对每份试卷生成 source spans、visual lines、anchors 和 ownership assignments；
4. 验证 visual-line geometry、reading order、region classification 和 excluded material；
5. 验证 alpha/Roman anchor hierarchy；
6. 验证 parent/child boundary、marks ownership 和 text leakage；
7. 验证所有 source span 都有唯一 ownership 结果；
8. 验证同一输入双跑 deterministic；
9. 生成跨试卷汇总报告；
10. 保持 candidate text、Stable IDs、Production 和 Frontend 不变。

---

## 3. 非目标

本阶段禁止：

- 修改 Production；
- 修改 Frontend；
- 修改 question rendering；
- 修改 candidate question text；
- 修改 Stable Question IDs；
- 修改 Parent IDs 或 Child IDs；
- 运行 10 PDF；
- 运行 216 PDF；
- 执行正式 Canonical Boundary Contract；
- 将结果写入 production store；
- 新增 serialization closeout；
- 新增 hash/manifest 流程；
- 因单个 fixture 失败而静默跳过；
- 在失败后自动扩大范围；
- 将未验证结果写成 PASS。

本阶段可以新增或修改：

- 3-PDF runner；
- fixture selection logic；
- validation aggregation；
- evidence output；
- 只用于测试的 fixture assertions。

除非 3-PDF 运行暴露明确缺陷，否则不得修改 ownership 核心算法。

### 4.2 Fixture B：0478 Child Boundary 与 Marks 风险

如果 corpus 中该试卷不存在，必须：

4. 不得悄悄换成普通简单试卷。

## 10. Anchor 验证

每份试卷必须区分：

```text

```

必须验证：

### 10.1 Alpha Child

```text
(a)
(b)
(c)
(d)
```

在存在 top-level parent context 时必须形成稳定 sibling hierarchy。

### 10.2 Roman Child

```text
(i)

(iii)
```

必须在正确 parent 下形成 Roman child。

### 10.3 Alpha/Roman Ambiguity

必须继续验证：

```text

```

中的 `(i)` 是 Roman child。

同时避免将：

```text
(h) → (i) → (j)
```

中的 `(i)` 错判为 Roman child。

### 10.4 Non-Structural Roman Token

必须继续验证：

```text

```

硬指标：

```text
duplicateStructuralAnchorCount = 0

unresolvedStructuralTokenCount = 0
```

