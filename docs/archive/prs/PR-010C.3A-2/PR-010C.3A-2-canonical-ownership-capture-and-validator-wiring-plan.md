## 1. 阶段目标

本阶段用于完成 Canonical Question Boundary Contract 的真实接入与所有权证据捕获。

当前已确认：

- PR-010C.3A 的 dry-run 执行链路可以完整运行；
- 7 个 evidence artifacts 已成功生成；
- `productionWrite=false`；
- 当前唯一 raw issue 确实由 validator 直接产生；
- 但该 issue 来自 `questionRenderingContract.validateQuestionRenderingContract v1.0.0`；
- 当前没有执行 `CANONICAL_QUESTION_BOUNDARY_CONTRACT v1.1.0`；
- `ownershipAssignmentsCaptured=0`；

## 2. 当前阻塞问题

### 2.1 Validator 层级错误

当前实际执行的是：

```text
questionRenderingContract.validateQuestionRenderingContract
validatorVersion = 1.0.0
```

该 validator 主要检查前端是否存在可显示内容，例如：

```text
questionText
displayText
layout blocks
```

它不能验证 Canonical Question Boundary Contract 的核心要求：

- 一个 semantic span 是否恰好只有一个 owner；
- sibling child 是否发生重叠；
- mark allocation 是否进入题干；
- structural anchor 是否被错误识别；
- next question 是否泄漏；
- source trace 是否完整；
- topology 是否经过审查。

本阶段必须实际执行：

```text
CANONICAL_QUESTION_BOUNDARY_CONTRACT
contractVersion = 1.1.0
```

---

### 2.2 Ownership Assignment 没有被保留

当前运行报告显示：

```text
ownershipAssignmentsCaptured = 0
```

现有 candidate model 没有持久化 explicit span ownership assignments。

因此目前无法证明：

```text
每个 semantic span 恰好属于一个 canonical owner
```

本阶段必须在 ownership 信息仍存在于内存的阶段增加只读 capture hook。

## 4. Ownership Capture 设计

### 4.1 Capture 时机

必须在以下信息仍然存在于内存时捕获：

```text
PDF source spans
→ geometry ordering
→ visual line grouping
→ anchor classification
→ ownership assignment
→ canonical serialization
```

Capture hook 必须位于 canonical serialization 之前。

如果 ownership assignment 当前从未被显式构建，必须报告：

```text
OWNERSHIP_MODEL_NOT_IMPLEMENTED
```

不得伪造 assignments。

---

### 4.2 Source Span DTO

每个 source span 必须输出为 plain JSON DTO：

```json
{
  "spanId": "stable-span-id",
  "paperId": "9618-2024-ON-12-QP",
  "page": 1,
  "blockIndex": 0,
  "lineIndex": 0,
  "spanIndex": 0,
  "text": "Index Register",
  "bbox": {
    "x0": 0,
    "y0": 0,
    "x1": 0,
    "y1": 0
  },
  "globalOrder": 0,
  "visualOrder": 0,
  "classification": "SEMANTIC_TEXT",
  "assignedOwner": {
    "ownerType": "CHILD_QUESTION",
    "ownerId": "9618-2024-ON-12-Q3-A",
    "ownerPath": ["a"]
  },
  "anchorRelationship": {
    "precedingAnchorId": null,
    "terminatingAnchorId": null
  }
}
```

---

### 4.3 Span ID 要求

`spanId` 必须：

- 在同一次 dry-run 中唯一；
- 对相同输入重复运行时稳定；
- 不依赖数组临时位置；
- 能够关联 source span、ownership assignment 和 validator issue；
- 能在 report 中直接追溯。

建议组成：

```text
paperId
page
blockIndex
lineIndex
spanIndex
normalized text hash
```

不得仅使用：

```text
array index
random UUID
generatedAt
```

---

### 4.4 Classification Enum

至少支持：

```text
SEMANTIC_TEXT
STRUCTURAL_ANCHOR
MARK_ALLOCATION
RESPONSE_AREA
EXCLUDED_MATERIAL
TABLE_CELL
CODE_BLOCK
UNRESOLVED
```

如果当前项目有更细分类，可以扩展，但必须在报告中列出 registry。

---

### 4.5 Owner Type Enum

至少支持：

```text
PARENT_PREAMBLE
CHILD_QUESTION
NESTED_CHILD_QUESTION
MARK_ALLOCATION
RESPONSE_AREA
NEXT_TOP_LEVEL_QUESTION
EXCLUDED_PAGE_MATERIAL
UNRESOLVED
```

每个 semantic span 必须满足：

```text
owner count = 1
```

以下情况必须由 Canonical validator 报错：

```text
owner count = 0
owner count > 1
owner type invalid
owner path invalid
```

## 5. Visual Line 和 Anchor Evidence

### 5.1 Visual Line DTO

每条 visual line 至少包含：

```json
{
  "visualLineId": "stable-line-id",
  "paperId": "9618-2024-ON-12-QP",
  "page": 1,
  "visualOrder": 0,
  "spanIds": [],
  "bbox": {
    "x0": 0,
    "y0": 0,
    "x1": 0,
    "y1": 0
  },
  "text": "..."
}
```

必须能够证明：

```text
visual line order
```

来自 geometry，而不是 PDF content array 的原始顺序。

---

### 5.2 Anchor DTO

每个 structural anchor 至少包含：

```json
{
  "anchorId": "stable-anchor-id",
  "paperId": "9618-2024-ON-12-QP",
  "spanIds": [],
  "anchorType": "TOP_LEVEL_QUESTION|ALPHA_CHILD|ROMAN_CHILD|MARK_ALLOCATION",
  "label": "(ix)",
  "ownerPath": ["a", "ix"],
  "classificationConfidence": 0.0,
  "context": {
    "precedingText": "Index Register",
    "followingText": ""
  }
}
```

对于 `(IX)` 这类 token，classifier 必须考虑上下文。

不得仅因文本匹配 Roman numeral 就认定它是 structural child。

## 14. Hard Acceptance Criteria

本阶段通过必须同时满足：

1. `contractVersion = 1.1.0`；
2. `canonicalValidatorExecuted = true`；
3. `renderingValidatorExecuted = true`；
4. Canonical issues 与 Rendering issues 分开；

7. source spans 具有稳定唯一 `spanId`；
8. source spans 包含 bbox；
9. source spans 包含 visual order；
10. source spans 包含 classification；
11. semantic spans 具有明确 assigned owner；
12. Canonical validator 检查 single-owner invariant；
13. Canonical validator 检查 boundary isolation；
14. Canonical validator 检查 mark separation；
15. Canonical validator 检查 structural anchor context；
16. source trace gaps 被明确列出；
17. `displayText` fallback 不得隐藏 source trace gap；
18. `(IX)` context 被单独验证；
19. artifact SHA-256 完整；
20. dry-run 可重复；
21. Stable IDs 不变；
22. candidate text 不变；
23. Production write 保持 false；
24. 不使用 semantic diff 构造 issue；
25. 不人工维持旧 issue 数量。
