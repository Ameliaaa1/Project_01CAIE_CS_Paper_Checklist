# Solution Proposal

## PR-018 --- Eliminate Barcode Pollution and Ensure Text Quality Metric Consistency

------------------------------------------------------------------------

# Objective

This PR only addresses the current P0 release blocker:

``` text
TEXT_QUALITY_METRIC_INCONSISTENT
```

No other parser behavior should be modified.

This PR must **NOT** change:

-   Question Split
-   Stable Question ID
-   Parent / Leaf Question
-   Marks
-   Question Boundary
-   Response Area extraction

------------------------------------------------------------------------

# Background

The latest PyMuPDF inspection confirms that suspicious glyphs are
**NOT** generated by OCR.

Instead, they originate from machine-readable barcode regions that are
currently entering the Canonical Text pipeline.

Example:

``` text

```

These glyphs are **NOT** question content.

They must never enter:

-   normalizedText
-   displayText
-   embeddings
-   search index

------------------------------------------------------------------------

# Root Cause

Current pipeline still allows non-question spans to enter Canonical
Text.

Current flow is effectively:

``` text
Raw PDF
    ↓
Extract spans
    ↓
Merge page text
    ↓
Canonical Text
    ↓
Metric
```

instead of

``` text
Raw PDF
    ↓
Span
    ↓
Region Classification
    ↓
QUESTION_CONTENT only
    ↓
Canonical Text
    ↓
Metric
```

Therefore:

``` text
normalizedText

contains

ċ
ĥ
ą

while

normalizedSuspiciousGlyphCount

==

0
```

The metric and final string become inconsistent.

------------------------------------------------------------------------

# Scope

This PR only changes:

-   Region admission
-   Canonical Text Builder
-   Metric calculation timing
-   Validator

No parser logic should be redesigned.

------------------------------------------------------------------------

# Implementation

## Step 1 --- Introduce Barcode Region

New Region Type:

``` text
BARCODE
```

Classification signals:

-   font == AllAndNone2 (strong signal only)
-   font size \<= 5.5
-   located inside barcode bands
-   contains abnormal Unicode
-   contains unexpected control characters
-   extremely narrow bounding box

Do **NOT** rely on font name alone.

------------------------------------------------------------------------

## Step 2 --- Region Classification Order

``` text
BARCODE
↓
MARGIN
↓
HEADER
↓
FOOTER
↓
RESPONSE_AREA
↓
VISUAL
↓
QUESTION_CONTENT
```

Barcode should never become Footer.

------------------------------------------------------------------------

## Step 3 --- Canonical Text Builder

Replace:

``` text
All Spans
↓
join()
↓
replace()
↓
normalizedText
```

with:

``` text
Question Spans
↓
Region Filter
↓
QUESTION_CONTENT only
↓
Build displayText
↓
Normalize
↓
normalizedText
```

Only `QUESTION_CONTENT` may contribute to Canonical Text.

------------------------------------------------------------------------

## Step 4 --- Metric Calculation

Metrics must always be calculated **after** the final strings are
generated.

``` text
displayText
↓
normalizedText
↓
Metric
```

The Builder should return:

``` ts
{
  displayText,
  normalizedText,
  metrics
}
```

------------------------------------------------------------------------

## Step 5 --- Validator

Validator must never trust stored metrics.

``` text
Read Staging
↓
Recompute Metrics
↓
Compare
↓
Validation Result
```

If:

``` text
stored != recomputed
```

raise:

``` text
TEXT_QUALITY_METRIC_INCONSISTENT
```

------------------------------------------------------------------------

## Step 6 --- Publish Gate

``` text
Metric Consistent
AND
No Suspicious Glyph
↓
READY_TO_PUBLISH
```

Otherwise:

``` text
BLOCKED
```

**Very Low**

# Success Criteria

-   Barcode spans never enter Canonical Text.
-   Footer never enters Canonical Text.
-   Margin never enters Canonical Text.
-   Region Classification passes Golden Fixture.
-   Validator independently recomputes metrics.
-   Stored metrics equal recomputed metrics.
-   Publish blocks inconsistent staging.
-   Existing Question IDs remain unchanged.
-   Existing Marks remain unchanged.
-   Existing Question Split remains unchanged.
